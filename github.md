# Connect GitHub

GitHub is a website where people keep the files of a project, usually software or a website, with a full history of every change. Connecting it lets your Bots work on those projects for you, in the VectoCode area of the app.

If you do not use GitHub, you can skip this feature. It is only for people who already have projects there, or whose developer or Bot builds a website or app for them.

## Before you start

- You need a **GitHub account** and at least one project (GitHub calls it a repository) in it.
- You do **not** give VectoBots your GitHub password. A GitHub page opens, and your password stays with GitHub.
- You choose which projects Bots may see.
- Connecting is free. Any AI work your Bots do afterwards is paid like any other work. See [Costs]({{ '/costs/' | relative_url }}).

## Three things to know first

- Bots only see what you allow. You can change that on GitHub whenever you like.
- When you start a project, your Bots get **their own working copy**. They do not edit your original directly.
- Your work is saved to GitHub **only when you say so**.

## How to connect

The GitHub section is in **Apps**. On a laptop, click the Apps icon at the bottom of the left column. On a phone, tap **More** at the bottom, then **Apps**.

1. Open **Apps** and find **GitHub**. You see the heading **Connect GitHub** and "So your Bots can work on your projects."
2. Tap **Sign in with GitHub**. A GitHub page opens.
3. **The first time only**, GitHub shows **one Create button** for the VectoBots App. Approve it once. GitHub asks you to approve once, and then you choose which projects Bots may see. Choose **all projects**, or only the ones you pick.
4. GitHub sends you back. The app says "GitHub is connected" and shows **Pick a project**.

The screen lists the three steps as: Sign in with GitHub, Choose what Bots can see, Come back and pick a project.

## How to start a project

1. In **Pick a project**, find the one you want. Use **Find a project** to search. Each row says Private or Public and when it was last updated.
2. Tap **Start** next to it.
3. The app asks "Start a project from [name]?" Tap **Start project**, or **Cancel**.
4. The row shows "Getting it ready…", then "Project ready."

## Every button and line explained

- **Refresh.** Reloads the list. Use it after you add a new project on GitHub. The app says "Up to date."
- **Find a project.** Filters the list as you type. "No match" means nothing fits; "No projects yet" means you have not chosen any on GitHub yet.
- **Choose more on GitHub.** The link under the list. It opens GitHub so you can allow more projects. Come back and tap **Refresh**.
- **Try again / Remove.** Appear on a project that failed to copy. The row says "Could not copy:" with the reason. **Try again** repeats the copy. **Remove** takes it off the list ("Removed").
- **Sign out of GitHub.** Disconnects the app from your GitHub account. The app says "Signed out of GitHub."

## Examples

A consultant has a small website on GitHub. She connects, allows only that one project, and taps **Start**. She asks a Bot in VectoCode to fix a typo and add a page. The Bot works on its own copy. When she is happy, she tells it to save the work to GitHub.

A coach has several projects, among them a private one with client forms. She chooses only the public website project when GitHub asks which projects Bots may see. The private one stays invisible to her Bots.

## Common problems

- **"Not ready yet", with a reason underneath, or "Needs the Vault key".** The app cannot hold your GitHub connection safely until the Vault key is set up. The reason underneath says what is missing.
- **"GitHub did not finish. Try again."** You left GitHub before it finished, or it failed. Tap **Sign in with GitHub** again.
- **I do not see my project.** You have not allowed it yet. Tap **Choose more on GitHub**, allow it, then **Refresh**.
- **"Could not copy".** Tap **Try again**. If it keeps failing, tap **Remove** and start it again.
